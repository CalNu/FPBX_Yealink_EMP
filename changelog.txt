1.1.8
• Fixed: closing the Manually Add Device / Scan Subnet windows no longer reloads the page unless a device was actually added, and the reload now opens Device Manager directly instead of flashing Global Settings first.
• Fixed: the HTTP->HTTPS redirect check now really requests http://<server>/PhoneSettings/ and /tftpboot/ on port 80 and looks for a redirect to https (it used to only test whether port 83 was open, so adding a redirect changed nothing). It runs on every page load, not just at install.
• Added: "HTTP Shift Port" box next to PBX Server IP in Global Settings (default 83). While a redirect is detected, provisioning, vpn.tar, ringtone and logo/wallpaper URLs use this port. Clicking the box lists suggested ports; ports already in use are flagged and a warning is shown if you pick one. Save Global Settings and rebuild devices after changing it.
• Fixed: setup-root.sh granted the sudo rule only to the user named in Apache's envvars (www-data on the FreePBX distro) while PHP actually runs as asterisk, so the banner never cleared. It now grants every user the web server/PHP-FPM processes run as, plus asterisk, and self-tests each. The banner shows which user PHP runs as and what sudo said when the rule is missing; the helper points to Connectivity > Firewall when the FreePBX Firewall is active.
• Added: one-time setup-root.sh. It installs a root-owned helper and a narrow sudo rule so Apache's listener for the shift port is created from the module page (Save Global Settings, or the "Set up port now" button) with no more SSH. It serves only /PhoneSettings and /tftpboot over plain HTTP and opens the port in ufw/firewalld if active. Until it has been run, the page shows a click-to-copy banner with the command. The port's listener uses its own document root holding only links to /PhoneSettings and /tftpboot, so a redirect rule in the web-root .htaccess or a server-wide Redirect can't catch it; if something still does, the banner shows what the redirect points to and a "Find the redirect rule" button lists the Redirect/Rewrite lines in Apache's config. The port box's redirect-detected text is its hover tooltip, and the box itself is only shown while a redirect is detected. install_tftp.sh now also runs setup-root.sh --yealink-only, so a server that needs TFTP set up gets the shift-port permission at the same time.
• Fixed: Edit MAC Address now only changes the MAC. The phone's .cfg is renamed with its contents untouched (template, extension, keys, overrides stay), and if VPN is enabled the key package is renamed to match and openvpn.url in the cfg is updated. Press Enter or click away to apply, Escape to cancel. Previously the edit ran as part of a rebuild and lost the template/extension assignment.
• Changed: the Memory Keys button in the per-device Edit window is now hidden for phones that have no memory keys (no built-in ones and no expansion module on the template).
• Changed: tooltips - template pencil is now "Edit Template Overrides", MAC pencil "Edit MAC Address", and the eye icon "View Current CFG".

1.1.7
• Added: per-device overrides. A pencil button next to each device's template (Device Manager) opens an Edit window with Notifications toggles, Line / Memory / Programmable Keys windows, default account ringtone and a custom key/value box. Only values that differ from the template are written, in a DEVICE OVERRIDES block at the end of the phone's .cfg; template saves and rebuilds preserve it.
• Changed: turning a phone's VPN off now points openvpn.url at PhoneSettings/fakekeys/null.tar instead of clearing it, so the phone stops retrying without a reboot. install.php creates the empty null.tar; uninstall.php removes it.
• Added: TFTP check on install and a banner on the module page (with a click-to-copy command) when TFTP is missing or not running; install_tftp.sh installs TFTP, links /tftpboot into /var/www/html, sets permissions and opens UDP 69.

• When a programmable key's type is changed away from one that used Line, Value, History or (for SoftKey 1-4) Label - including reverting back to the default type - any of those fields no longer used by the new type are now explicitly cleared (%NULL%) in the generated config, instead of leaving the phone with the previous type's stale value.
